# 故障排查

## 找不到 Python

运行：

```powershell
python --version
```

需要 Python 3.10 或更高版本。公司设备如需软件审批，按正常审批流程安装，不要使用来源不明的 Python 包。

## PowerShell 阻止脚本

不要修改全局执行策略或关闭终端防护。可以先阅读 `install.ps1`，再联系桌面支持或平台管理员按公司规则放行。

## Agent 看不到工具

1. 确认已经把 `mcp-config.local.json` 中的 `portable-search` 项复制到 Agent 配置。
2. 确认配置中的 Python 和脚本路径仍然存在。
3. 重启 Agent，而不只是新建对话。
4. 运行 `.\verify.ps1`，先排除本地协议问题。
5. 确认该产品真的支持 MCP；只支持模型 API 不等于支持外部工具。

## 协议检查成功，但联网检查失败

运行：

```powershell
.\verify.ps1 -Live
```

常见原因包括公网出口限制、代理要求、DNS 问题、搜索后端临时限流或上游页面不可用。稍后重试一次；如果持续失败，应停止依赖免费后端，而不是不断提高调用频率。

## 新闻结果不是今天

- 调用 `search_news` 时传入 `timelimit: "d"`。
- 工具会剔除不属于运行电脑当地当天、缺少日期或日期无法解析的结果；空结果比旧闻冒充今日新闻更可信。
- 仍要检查每条结果的 `published_at`，不要只看标题中的“今日”“最新”。
- 打开原文区分文章发布时间、页面更新时间和事件发生时间。
- 没有可核对日期的条目不能作为“今日新闻”的证据。
- 对时效要求很高的任务，应改用有明确更新时间、配额和服务承诺的数据源。

## 结果为空或时好时坏

公开免费搜索没有稳定性承诺。默认 `auto` 会尝试多个后端，但仍可能失败。不要在短时间内高频重试，以免触发更严格的限制。

## 搜索结果质量不够

缩小查询范围，加入官方机构、文档类型、地点或日期。重要任务应要求 Agent 输出来源链接，并由用户打开原文复核。需要读取网页全文时，应使用经过安全审核的内容读取工具；本工具故意不提供任意 URL 抓取。
