## 实时搜索测试

命令：

```powershell
$env:RUN_LIVE_SEARCH_TESTS='1'
python -m pytest -q tests\test_live_search.py
```

最终实现完成后连续执行 3 轮，每轮包括：

1. 英文网页搜索；
2. 中文网页搜索；
3. 图片搜索；
4. 近一天新闻搜索与发布时间检查。

结果：3 轮全部通过，共 12/12 项通过。每轮耗时约 7–10 秒。

网页与图片检查每轮均返回有效公开 URL。新闻检查的通过标准是：返回的每一条新闻都必须有可解析时间，并通过当地日期过滤；当没有合格新闻时允许返回空结果和明确提示。

另外连续探测 5 次同一“近一天 AI 新闻”查询，过滤后结果数分别为：`1、7、0、0、2`。其中 3/5 轮找到至少一条当地当天且有可解析时间的新闻；2/5 轮上游返回了内容，但没有任何结果通过本地时效检查。5 轮均未发生上游请求异常。

这些数字是当次网络条件下的观测，不是固定配额或未来保证。测试还发现上游曾把 7 天前的结果放进“近一天”结果中，因此加入本地强制时效过滤。

## 新闻时效问题与修复

第二轮早期测试发现，上游有时返回标准 ISO 时间，有时返回类似“44 minutes ago”的相对时间，前面还可能混有栏目名称。直接把该字段交给模型，会导致排序和“今日新闻”判断不可靠。

修复后：

- 标准时间统一转换为 UTC ISO 时间；
- 分钟、小时、天的英文相对时间转换为 UTC ISO 时间；
- 无法解析的值置空，不冒充有效发布时间；
- 有日期结果按发布时间倒序，无日期结果排在末尾；
- 传入 `d` 时，只保留运行电脑当地当天的有日期结果；
- 传入 `w/m/y` 时，只保留 7/31/365 天内的有日期结果；
- 实时测试要求至少有一条通过本地过滤的新闻，且所有结果距测试时刻不超过 26 小时。

本地过滤采用运行电脑的当地日期，解决了“上游近一天过滤仍返回旧闻”的问题。仍需注意：发布时间字段由上游提供，工具无法证明字段真实；Agent 和使用者仍需核对原文。

## 后端可用性测试

使用相同查询分别测试：

| 后端 | 结果 |
|---|---|
| 固定 `duckduckgo` | 当次不可用，0 条结果 |
| 默认 `auto` | 可用，3 条结果 |

因此默认保留元搜索 `auto`，不宣传为“只使用 DuckDuckGo”。这提高了当次可用性，但结果来源、排序和隐私政策可能随实际后端变化。

## 尚未证明的能力

本次测试没有证明以下事项：

- 长期、高并发或批量稳定性；
- 任何免费后端的固定配额；
- 分钟级实时新闻和所有结果日期都准确；
- 不同国家、网络代理和企业出口下结果一致；
- 网页正文抓取、付费墙内容读取或企业内部资料访问；
- 搜索摘要足以支撑高风险业务结论。

这些边界也是正式使用时必须保留的限制。
