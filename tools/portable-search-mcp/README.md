# Portable Search MCP｜通用联网搜索工具

给支持 MCP 工具调用的本地模型、Agent、IDE、CLI 和自动化流程增加公开互联网搜索能力。它不要求商业搜索 API Key，但运行它的电脑必须可以访问公网。

> 最短路径：下载 ZIP → 解压 → 运行 `install.ps1` → 把生成的 MCP 配置复制到你的 Agent 工具中 → 运行 `verify.ps1 -Live`。

## 它解决什么问题

模型只包含训练时学到的知识。即使模型部署在公司内网或个人电脑上，也不会自动知道最新网页和新闻。Portable Search MCP 把公开网络搜索包装成标准 MCP 工具，让 Agent 可以主动检索标题、链接、摘要、图片地址和新闻发布时间，再把结果交给模型。

它解决的是“Agent 缺少公开网络搜索工具”，不是“模型本身不会推理”，也不是企业内部知识库建设。

## 为什么已有工具能搜索，还需要它

很多桌面聊天工具已经带搜索按钮。只在一个客户端里聊天，而且内置搜索的效果、时效和安全边界都满足要求时，直接使用内置功能更简单，不必安装本工具。

Portable Search MCP 的价值在于搜索能力可以独立复用：

| 对比项 | 客户端内置搜索 | Portable Search MCP |
|---|---|---|
| 使用位置 | 通常只在该客户端内 | 任何兼容 MCP 的 Agent、IDE、CLI 或服务器流程 |
| 与模型关系 | 常与客户端配置绑定 | 与模型供应商和模型版本解耦 |
| 自动化 | 以人工对话为主 | 可用于无界面、批处理和多 Agent 工作流 |
| 可检查性 | 取决于客户端开放程度 | 代码、参数边界、依赖和测试均可检查 |
| 团队复用 | 每个人分别配置 | 同一 ZIP、同一接口、同一测试方法 |
| API Key | 视客户端或搜索服务而定 | 当前方案不要求搜索 API Key |

它的定位是通用搜索基础组件，不是另一个聊天界面。

## 适合使用的场景

- 本地或私有部署模型已经接入 Agent/Harness，但缺少联网搜索工具。
- 希望同一套搜索能力同时用于多个 MCP 客户端或不同模型。
- 需要在 IDE、CLI、定时任务或服务器 Agent 中执行无界面搜索。
- 想先做低成本 PoC，不准备申请商业搜索 API。
- 需要把安装包、依赖、参数限制和测试结果交给其他同事复核。

## 不适合使用的场景

- 当前聊天工具的内置搜索已经完全满足个人使用。
- 模型或客户端不支持 MCP，也没有其他工具调用层。
- 运行环境禁止访问公网。
- 搜索词包含客户数据、密码、令牌、未公开业务信息或其他敏感内容。
- 需要查询公司 Wiki、网盘、数据库或内部文档；应使用公司批准的内部连接器或 RAG。
- 需要有服务等级承诺、稳定配额、分钟级新闻保证或可重复的固定搜索结果。
- 医疗、法律、财务、审计等高风险判断只依赖搜索摘要而不核对原文。

## 提供的工具

- `search_web`：公开网页标题、URL 和摘要。
- `search_news`：公开新闻标题、URL、摘要、来源和发布时间。
- `search_images`：公开图片标题、原图 URL、缩略图和来源。

旧工具名 `ddgs_search`、`ddgs_news`、`ddgs_images` 仍可调用，但不再展示给新用户。

每次最多返回 20 条结果，搜索词最多 500 个字符。服务不会把搜索词或上游错误详情写入标准输出。

## 实际搜索表现

2026-08-05 的最终基准覆盖 30 个场景、每个 3 轮，共 90 次实时请求。90/90 请求成功；网页和图片 66/66 轮有结果；新闻 24/24 轮有结果，返回新闻的日期完整率为 100%；URL 有效率和单次结果去重率均为 100%；响应时间 P50 为 2.537 秒、P95 为 9.055 秒。

搜索精度仍取决于查询写法。6 个“找指定官网”任务各跑 3 轮：普通语句把目标官网排进前 5 的比例为 16/18；加入 `site:` 域名限制后，目标官网 18/18 排在第 1 位。两次普通语句漏检均来自人民银行官网，说明导航改写和重排提高了命中率，但不能替代明确域名。

因此推荐把提示词写成：

```text
请先用 search_web 搜索公开资料。需要权威来源时，在查询词中加入 site:目标域名；
返回结论前列出来源标题和 URL，并打开关键原文核对，不要只依据摘要。
如果是今天的新闻，调用 search_news 并设置 timelimit="d"；没有通过日期检查的结果时明确说“未找到合格的当天新闻”，不要用旧闻补齐。
```

复跑方法、查询清单、优化前后对比和逐轮匿名化指标见[测试报告](docs/TEST-REPORT.md)与[最终基准数据](docs/benchmark-2026-08-05-v3.json)。

## 安装和验证

面向普通用户的步骤见 [QUICKSTART.md](QUICKSTART.md)。

```powershell
.\install.ps1
.\verify.ps1 -Live
```

安装脚本会：

1. 检查 Python 3.10 或更高版本；
2. 在当前目录建立独立 `.venv`；
3. 安装锁定版本的依赖；
4. 生成只适用于本机的 `mcp-config.local.json`；
5. 执行不联网的 MCP 协议检查。

`mcp-config.local.json` 包含本机安装路径，不要把它再次打包或转发。把其中的 `portable-search` 配置复制到 Agent 的 MCP 配置区后，重启 Agent。

## 新闻时效怎么判断

当用户问“今天”或“最新”时，Agent 应调用 `search_news` 并传入 `timelimit: "d"`。工具会返回 `published_at`，统一相对时间格式，并把结果按时间倒序排列。

由于公共搜索引擎的时间过滤并不可靠，本工具会再按运行电脑的当地日期过滤：`d` 只保留当地当天且有可解析发布时间的新闻；`w/m/y` 分别只保留 7/31/365 天内且有日期的新闻。没有合格结果时返回空数组，不用旧闻填充。

本地过滤仍不能证明上游时间字段一定真实。页面日期、文章更新时间和事件发生时间也可能不同，重要结论必须打开原文核对。

## 搜索来源和稳定性

网页和图片搜索使用 `ddgs` 多搜索引擎聚合库。新闻优先使用带发布时间的公开 Google News RSS；RSS 不可用或没有合格结果时，再调用 `ddgs` 的 Bing、DuckDuckGo 和 Yahoo 新闻后端。所有新闻仍执行本地时间过滤。这些公开来源都不提供服务等级承诺，因此：

- 来源和排序可能随时间变化；
- 公开搜索端点可能限流或临时不可用；
- 免费访问没有正式配额或服务等级承诺；
- 不同网络和地区的结果可能不同。

如需固定 `ddgs` 后端，可以设置环境变量 `SEARCH_MCP_BACKEND`。该设置不关闭新闻 RSS；固定单一后端通常会降低回退能力。
