## 行为验收案例

`reality-grounding/references/evaluation-cases.md` 保存九类现实调查案例。`reality-strategy/references/evaluation-cases.md` 保存八类现实策略案例，覆盖办公室尴尬问题、邻居噪音、公共杯子、家人体检、群聊任务、合租费用、信息通道失败和问题来源判断错误。

这些案例用于检查 Agent 的实际回答。当前自动测试验证成对安装、记录结构和关键行为要求是否完整；案例文件存在不等于模型行为已经通过。

## 独立行为试跑

2026-09-02，把公开包中的两个 Skill 交给另一个验收 Agent，未提供预期答案，测试四个首次请求：邻居深夜噪音、公共杯子无人清洗、家人拒绝体检、群聊任务无人认领。四个回复都先询问了会改变路线且能凭日常观察回答的问题，没有在信息不足时直接给完整方案；每个回复都提出了可逆的观察或试探、要看的信号和下一轮反馈。

随后向其中两个案例补充现场信息。公共杯子案例删掉了群发提醒和投诉路线，利用“行政在午饭聊天时也在场”这一条件，通过向行政询问真实清洗规则，让规则说明同时成为当事人可以听见、又不必当场认错的信息。群聊案例利用“发起人没有分配权、用户没有隐性收益、延迟回复已经无效”这些信息，切断私聊用户兜底的旧通道，把无人认领的事实送到真正有分配权的主管面前。两轮都给出了观察信号、停止条件和失败后的换路。

这次试跑也发现两个缺口并已回写：询问应检查当前安排是否给用户或其他人带来隐性收益；延迟可能造成严重伤害时，应先判断紧急程度并转向合格的专业帮助。这是独立验收任务，但不是完全无历史的新用户冷启动，也没有覆盖不同模型和宿主，因此公开状态仍为候选。

## 尚不能由自动测试证明

- 任意 Agent 都能发现并自动触发两个 Skill；
- 不同模型在所有真实任务中稳定执行调查顺序；
- 用户提供的事实和外部来源一定真实；
- 不同 Agent 都能在真实对话中稳定追问、设计非直接路线并持续跟进；这仍需新的独立前向对话验证。
