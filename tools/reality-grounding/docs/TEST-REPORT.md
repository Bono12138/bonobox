## 行为验收案例

`reality-grounding/references/evaluation-cases.md` 保存十类现实调查案例。`reality-strategy/references/evaluation-cases.md` 保存九类盲测案例。新增案例专门检查 Agent 能否从混乱的多人事项中找回原始诉求，还原参与方与钱、货、合同、时间关系，同时避免长问卷和自作主张补充事实。

这些案例用于检查 Agent 的实际回答。当前自动测试验证成对安装、记录结构和关键行为要求是否完整；案例文件存在不等于模型行为已经通过。

## v0.5.0 发布前盲测

2026-09-02，另开两个无历史上下文的验收 Agent，只提供公开版 Skill 和首次请求，不提供标准答案，也不允许读取评测文件。

第一个请求故意把一项多人、多地的设备交易讲得很乱，同时把“融资”“跨境付款”和“代收代付”混在一起。验收回复没有直接研究资金通道，也没有连续追问账户、费率等细节。它先整理成三种具体结构，再用一条消息确认签约关系、货物流和第一笔资金。这次只验证了原始诉求还原与低负担询问，没有验证后续交易方案。

第二个请求只说明老板称老供应商可靠、包装反复破损、采购不敢更换、用户团队持续返工。验收回复没有把“可靠”当成真实原因，也没有直接提出换供应商。它先询问老板本人上次怎样回应、“可靠”具体指什么、用户和采购是否拥有小范围测试权，以及出错会影响什么。这次验证的是第一轮诊断门槛；由于没有继续提供现场反馈，不能据此声称完整策略已经跑通。

完整输入、完整回复、宿主信息和测试边界见 [v0.5.0 发布前盲测记录](evaluations/20260902-v0.5.0-blind-tests.md)。

## 尚不能由自动测试证明

- 任意 Agent 都能发现并自动触发两个 Skill；
- 不同模型在所有真实任务中稳定执行调查顺序；
- 用户提供的事实和外部来源一定真实；
- 不同 Agent 都能在真实对话中稳定追问、设计非直接路线并持续跟进；这仍需新的独立前向对话验证。
